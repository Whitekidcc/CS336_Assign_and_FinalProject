# 官方测试文件阅读指南

本指南逐项解释当前仓库 `tests/` 下的测试；测试代码、fixture 和快照均保持原样。对应 Problem 标识以随附 Spring 2026 PDF Version 26.0.3 为准。这里描述**可观察的检查条件**，不提供实现方式。起始状态下适配器抛出 `NotImplementedError`，因此不能把当前测试失败理解为本地化造成的回归。

**单独运行规则：**在项目根目录执行 `uv run pytest tests/文件名.py::测试函数名`。下表每行给出真实测试函数名，将其接到该节写出的文件命令后即可。例如 `uv run pytest tests/test_data.py::test_get_batch`。运行整份文件则省略 `::测试函数名`；运行全部测试的官方命令为 `uv run pytest`。快照在 `tests/_snapshots/`，不要更新或修改。

## 共用 fixture 与比较方式

`tests/conftest.py` 提供 `numpy_snapshot`（`.npz` 数值快照）、`snapshot`（`.pkl` 对象快照）及从 `tests/fixtures/ts_tests/model.pt` 读取的 `ts_state_dict`。数值快照通常用 `numpy.testing.assert_allclose` 比较，并在测试处覆盖容差；形状不匹配也会失败。`tests/common.py` 提供 fixture 路径和 GPT-2 字节到可打印 Unicode 字符的辅助映射；它不是要求学生照搬的实现。`tests/__init__.py` 为空。`tests/adapters.py` 是入口，参数与返回值另见[适配接口阅读指南](适配接口阅读指南.md)。这些辅助文件都没有可单独运行的 `test_...` 函数。

模型 fixture 的常用数值：`batch_size=4`、`n_queries=12`、`n_keys=16`、`n_heads=4`、`d_head=16`、`d_model=64`、`d_ff=128`、`vocab_size=10_000`、`n_layers=3`、`theta=10000.0`。`q` 为 `(4, 12, 64)`，`k`/`v` 为 `(4, 16, 64)`，`mask` 为 `(4, 12, 16)` 的布尔张量，`in_embeddings` 为 `(4, 12, 64)`，`in_indices` 为 `(4, 12)`。某些测试从参考权重读取参数，并非所有期望值都直接写在测试文件里。

## `test_train_bpe.py` — BPE 训练

对应 PDF `train_bpe`；单独运行格式：`uv run pytest tests/test_train_bpe.py::函数名`。

| 测试函数 | 重要输入与预期检查 | 形状/边界 |
| --- | --- | --- |
| `test_train_bpe_speed` | `corpus.en`、`vocab_size=500`、特殊词元 `<\|endoftext\|>`；完成调用耗时须小于 1.5 秒。 | 时间阈值只针对该小语料，机器负载会影响测量。 |
| `test_train_bpe` | 同一输入；merge 列表必须与参考 merge 的**顺序及字节对**相等；词表的 key 集合和 value 集合分别与参考一致。 | 返回类型是 `dict[int, bytes]` 与 `list[tuple[bytes, bytes]]`；词表项的插入顺序不在此测试中比较。 |
| `test_train_bpe_special_tokens` | `tinystories_sample_5M.txt`、`vocab_size=1000`；除完整特殊词元外，其他词表值不得含 `b"<\|"`；还要匹配词表键集合、值集合和 merge 快照。 | 关注特殊词元作为独立单位时的边界；不修改 `.pkl` 快照。 |

## `test_tokenizer.py` — BPE Tokenizer

对应 PDF `tokenizer`；单独运行格式：`uv run pytest tests/test_tokenizer.py::函数名`。测试辅助 `get_tokenizer_from_vocab_merges_path` 将 GPT-2 文件读入并还原为原始 bytes，再通过 `get_tokenizer` 建立被测对象。**Roundtrip** 指 `decode(encode(text)) == text`；“matches_tiktoken” 指与 `tiktoken` 的 GPT-2 参照结果比较，具体检查以各行描述为准。文本输入不是 Tensor，因此没有 Tensor Shape；编码结果是 Token ID 序列，解码结果是字符串。

| 测试函数 | 重要输入与预期检查 | 边界或细节 |
| --- | --- | --- |
| `test_roundtrip_empty` | 空字符串编码后再解码仍为空字符串。 | 空输入。 |
| `test_empty_matches_tiktoken` | 空字符串的 ID 序列与 GPT-2 参照一致，逐 ID 解码列表为 `[]`。 | 同时核对两边解码结果。 |
| `test_roundtrip_single_character` | 单个 ASCII 字符 `s` 往返不变。 | 最短非空 ASCII 输入。 |
| `test_single_character_matches_tiktoken` | `s` 的 ID 与 GPT-2 参照一致，单 ID 解码为 `s`。 | 验证编码和解码。 |
| `test_roundtrip_single_unicode_character` | 单个 Unicode 字符 `🙃` 往返不变。 | 一个字符可由多个 UTF-8 字节构成。 |
| `test_single_unicode_character_matches_tiktoken` | `🙃` 的 ID 序列与 GPT-2 参照一致。 | 多字节字符。 |
| `test_roundtrip_ascii_string` | `Hello, how are you?` 往返不变。 | 空格与标点须保留。 |
| `test_ascii_string_matches_tiktoken` | 检查逐 ID 解码为 `['Hello', ',', ' how', ' are', ' you', '?']`，并检查双方解码回原文。 | 本测试中的 ID 列表相等断言被注释掉，不能把它读成正在比较 ID。 |
| `test_roundtrip_unicode_string` | `Héllò hôw are ü? 🙃` 往返不变。 | 重音字符、空格与 emoji。 |
| `test_unicode_string_matches_tiktoken` | 上述 Unicode 文本的 ID 与 GPT-2 参照一致，双方解码回原文。 | 跨多个 UTF-8 字节。 |
| `test_roundtrip_unicode_string_with_special_tokens` | 带三个 `<\|endoftext\|>` 的 Unicode 文本往返不变；逐 ID 解码结果中该特殊词元恰好出现三次。 | 相邻特殊词元及末尾特殊词元。 |
| `test_unicode_string_with_special_tokens_matches_tiktoken` | 同一文本的 ID 与允许特殊词元的 GPT-2 参照一致，双方解码回原文。 | `allowed_special` 参照设置。 |
| `test_overlapping_special_tokens` | 同时注册单个和双连写的结束词元；逐 ID 解码结果中分别各出现一次，并能往返。 | 重叠的特殊词元名称；双连写必须作为一个 token 保留。 |
| `test_address_roundtrip` | `address.txt` 整份文本往返不变。 | 文件输入。 |
| `test_address_matches_tiktoken` | `address.txt` 的 ID 与 GPT-2 参照一致，双方解码回原文。 | 文件内容中的标点、换行。 |
| `test_german_roundtrip` | `german.txt` 整份文本往返不变。 | 非纯英文文本。 |
| `test_german_matches_tiktoken` | `german.txt` 的 ID 与 GPT-2 参照一致，双方解码回原文。 | 多语言字符。 |
| `test_tinystories_sample_roundtrip` | `tinystories_sample.txt` 往返不变。 | 较长文本。 |
| `test_tinystories_matches_tiktoken` | 同一语料的 ID 与允许特殊词元的 GPT-2 参照一致，双方解码回原文。 | 语料中的文档分隔特殊词元。 |
| `test_encode_special_token_trailing_newlines` | 特殊词元后有换行的 fixture，其 ID 与 GPT-2 参照一致并可解码回原文。 | 特殊词元与尾随换行的边界。 |
| `test_encode_special_token_double_newline_non_whitespace` | 含双换行和非空白文本的 fixture，其 ID 与 GPT-2 参照一致并可往返。 | 换行/非空白组合。 |
| `test_encode_iterable_tinystories_sample_roundtrip` | 从文件迭代器使用 `encode_iterable` 收集 ID，解码应恢复整份原文。 | 流式输入。 |
| `test_encode_iterable_tinystories_matches_tiktoken` | 同样的迭代编码 ID 序列须与 GPT-2 参照一致，解码回原文。 | 分块不应改变结果。 |
| `test_encode_iterable_memory_usage` | 对 `tinystories_sample_5M.txt` 的 `encode_iterable` 调用限制额外地址空间约 1 MB。 | 仅 Linux 运行；非 Linux 自动跳过。 |
| `test_encode_memory_usage` | 普通 `encode` 在相同内存限制下被标记为 `xfail`，预期可能超出限制。 | 仅 Linux 运行；这是预期失败标记，不能当成额外的必须通过条件。 |

## `test_model.py` — Transformer 组件

对应 PDF 第 3 节；单独运行格式：`uv run pytest tests/test_model.py::函数名`。除最后一行外，以下测试都把结果与官方数值快照比较。表中具体维度来自当前 fixture；接口的通用维度仍以类型注解和 PDF 为准。

| 测试函数 / Problem | 重要输入与预期输出 | 关键 Tensor Shape 与边界 |
| --- | --- | --- |
| `test_linear` / `linear` | 给定参考 `w1` 权重与输入 embedding，比较 Linear 输出快照。 | 输入 `(4, 12, 64)`；权重 `(128, 64)`；输出 `(4, 12, 128)`。 |
| `test_embedding` / `embedding` | 给定参考词元嵌入权重与 Token ID，比较查询结果。 | Token ID `(4, 12)`；权重 `(10000, 64)`；输出 `(4, 12, 64)`。 |
| `test_swiglu` / `positionwise_feedforward` | 给定 `w1/w2/w3` 权重，比较 SwiGLU 输出。 | 输入、输出 `(4, 12, 64)`；内部宽度 `d_ff=128`。 |
| `test_scaled_dot_product_attention` / 同名 Problem | `q`、`k`、`v` 与布尔 `mask` 输入，比较注意力输出。 | `q=(4,12,64)`，`k=v=(4,16,64)`，`mask=(4,12,16)`，输出 `(4,12,64)`；query/key 长度不同。 |
| `test_4d_scaled_dot_product_attention` / 同名 Problem | 将前一组输入重排为含 head 维的 4D 张量，再比较注意力输出。 | `q=(2,2,12,64)`，`k=v=(2,2,16,64)`，`mask=(2,2,12,16)`；检查额外批次维。 |
| `test_multihead_self_attention` / `multihead_self_attention` | 从参考权重取 Q/K/V/O 投影，比较**不带 RoPE** 的 MHA 输出。 | 输入、输出 `(4,12,64)`；`n_heads=4`。 |
| `test_multihead_self_attention_with_rope` / `multihead_self_attention` | 同类权重，加 `theta` 和位置 ID，比较**带 RoPE** 的 MHA 输出。 | 输入、输出 `(4,12,64)`；位置 ID `(1,12)` 可广播；`max_seq_len=16`。 |
| `test_transformer_lm` / `transformer_lm` | 载入完整参考 `state_dict`，比较每个位置的未归一化输出。 | 输入 ID `(4,12)`；输出 `(4,12,10000)`；当前容差 `atol=1e-4, rtol=1e-2`。 |
| `test_transformer_lm_truncated_input` / `transformer_lm` | 将输入长度减半再比较输出。 | 输入 ID `(4,6)`；输出 `(4,6,10000)`；检查短于 `context_length=16` 的输入。 |
| `test_transformer_block` / `transformer_block` | 从参考模型抽出第一层权重，比较带 RoPE 的块输出。 | 输入、输出 `(4,12,64)`；权重键需对应接口说明。 |
| `test_rmsnorm` / `rmsnorm` | 使用参考 `ln1.weight` 与 `eps=1e-5`，比较 RMSNorm 输出。 | 输入、输出 `(4,12,64)`；归一化维度为末维。 |
| `test_rope` / `rope` | 给定 `theta` 与位置 ID，比较 RoPE 结果。 | 输入、输出 `(4,12,64)`；位置 ID `(12,)`。 |
| `test_silu_matches_pytorch` / `positionwise_feedforward` | 将逐元素 SiLU 输出与 `torch.nn.functional.silu` 参照比较。 | 输入、输出 `(2,5)`；测试中的高阶 API 只用于参照。 |

单独运行格式：`uv run pytest tests/test_nn_utils.py::函数名`。

| --- | --- | --- |

## `test_data.py` — 数据批次

对应 PDF `data_loading`；单独运行：`uv run pytest tests/test_data.py::test_get_batch`。

`test_get_batch` 使用一维 `np.arange(0,100)`，`batch_size=32`，`context_length=7`，在 CPU 上重复采样 1000 次。每次 `x`、`y` 都应为 `(32,7)`，且 `y` 相对于 `x` 的每个元素右移一个 Token ID。起始位置须位于有效范围 `[0,92]`，长期采样的出现次数还要落在基于期望值 ±5 个标准差的范围内。测试最后传入 `device="cuda:99"` 并期望出现 `RuntimeError` 或 `AssertionError`，用于确认 device 参数被使用；该异常块内的后续字符串断言在异常发生时不会执行，阅读时应以实际控制流为准。

## `test_serialization.py` — Checkpoint

对应 PDF `checkpointing`；单独运行：`uv run pytest tests/test_serialization.py::test_checkpointing`。

`test_checkpointing` 用输入宽度 100、输出宽度 10 的三层测试网络与学生提供的 AdamW 类训练 10 次，保存到临时 `checkpoint.pt`，再载入新模型和新优化器。它检查恢复的迭代数、模型 `state_dict` 键与各权重数值、优化器状态和参数组。测试辅助 `are_optimizers_equal` 对 Tensor 使用 `torch.allclose`，对非 Tensor 做直接比较。关注“模型权重、优化器状态、迭代号”三类恢复内容；此测试没有独立的 Tokenizer 或 Transformer Shape 要求。

## 测试与 PDF 的关系

PDF 第 6～7 节的生成、实验、曲线、资源核算和书面题，在当前 `tests/` 下没有对应自动化测试。测试通过也不等于全部作业完成。`tests/_snapshots/test_positionwise_feedforward.npz` 存在，但当前 `test_model.py` 没有同名测试函数；不要根据文件名推断新增测试。测试适配器中的文字若与 PDF 不一致，以 PDF 的作业要求为准，并在[适配接口阅读指南](适配接口阅读指南.md)中注明。
