# `tests/adapters.py` 中文接口阅读指南

本文件将官方适配器中现有 Docstring 的参数、返回值、形状与约束转为中文，帮助学生对照公开接口；`tests/adapters.py` 原文件及其执行逻辑保持不变。以下函数目前都抛出 `NotImplementedError`。PDF 的设计是：学生自行在 `cs336_basics/` 完成模块，再由学生在适配器中接入；适配器只负责连接，不承载核心算法。本地化没有替学生完成接入。

记号：`...` 表示任意前导维；`Int`、`Float`、`Bool` 是 `jaxtyping` 的类型标注；`weights` 通常取自官方 `state_dict`，名称与形状须按接口原样理解。这里保留所有参数名、关键、Tensor Shape 和 API 名。

## Transformer 基础模块

| 接口 / PDF Problem | 参数（中文释义） | 返回值及重要约束 |
| --- | --- | --- |
| `run_linear` / `linear` | `d_in`：输入末维宽度；`d_out`：输出末维宽度；`weights`：`Float[Tensor, " d_out d_in"]` 线性权重；`in_features`：`Float[Tensor, " ... d_in"]` 输入。 | `Float[Tensor, " ... d_out"]`，使用给定权重进行变换。原 Docstring 将前两个形参写成 `in_dim/out_dim`，实际签名是 `d_in/d_out`。 |
| `run_embedding` / `embedding` | `vocab_size`：词表项数；`d_model`：词元向量维度；`weights`：`Float[Tensor, " vocab_size d_model"]` 词元嵌入矩阵；`token_ids`：`Int[Tensor, " ..."]` 待查询的 Token ID。 | `Float[Tensor, " ... d_model"]`，即同样前导维的嵌入结果。 |
| `run_swiglu` / `positionwise_feedforward` | `d_model`：输入输出宽度；`d_ff`：内部上投影宽度；`w1_weight`/`w3_weight`：`(d_ff, d_model)`；`w2_weight`：`(d_model, d_ff)`；`in_features`：`Float[Tensor, " ... d_model"]`。 | `Float[Tensor, " ... d_model"]`。原 Docstring 中的 `load_state_dict` 与手动赋值只是适配器权重接入示例，不是完成的算法。 |
| `run_rmsnorm` / `rmsnorm` | `d_model`：末维宽度；`eps`：增加到分母的数值稳定项；`weights`：`Float[Tensor, " d_model"]`；`in_features`：`Float[Tensor, " ... d_model"]`，允许任意前导维。 | `Float[Tensor, " ... d_model"]`，输出形状与输入相同。 |
| `run_silu` / `positionwise_feedforward` | `in_features`：`Float[Tensor, " ..."]`，任意形状。 | `Float[Tensor, " ..."]`，逐元素应用 SiLU，形状不变。 |

## 注意力、位置编码与模型

| 接口 / PDF Problem | 参数（中文释义） | 返回值及重要约束 |
| --- | --- | --- |
| `run_rope` / `rope` | `d_k`：Q/K 向量宽度；`theta`：RoPE 参数；`max_seq_len`：如预计算时的最大序列长度；`in_query_or_key`：`Float[Tensor, " ... sequence_length d_k"]`；`token_positions`：`Int[Tensor, " ... sequence_length"]`，给出位置。 | `Float[Tensor, " ... sequence_length d_k"]`，形状不变。原说明举例位置形状 `(batch_size, sequence_length)`；类型标注允许任意前导维。 |
| `run_scaled_dot_product_attention` / `scaled_dot_product_attention` | `Q`：`Float[Tensor, " ... queries d_k"]`；`K`：`Float[Tensor, " ... keys d_k"]`；`V`：`Float[Tensor, " ... keys d_v"]`；`mask`：可选 `Bool[Tensor, " ... queries keys"]`。 | `Float[Tensor, " ... queries d_v"]`。`queries` 与 `keys` 可以不同；实际测试分别覆盖 3D 与 4D，并使用布尔 mask。 |
| `run_multihead_self_attention` / `multihead_self_attention` | `d_model`：输入输出宽度；`num_heads`：头数；`q_proj_weight`、`k_proj_weight`、`v_proj_weight`、`o_proj_weight`：均为 `(d_model, d_model)`；`in_features`：`Float[Tensor, " ... sequence_length d_model"]`。 | 同形状输出；这个接口**不使用 RoPE**。原 Docstring 还写到 `max_seq_len`，但实际签名没有此参数。 |
| `run_multihead_self_attention_with_rope` / `multihead_self_attention` | 比上一接口多 `max_seq_len`、`theta`、可选 `token_positions: Int[Tensor, " ... sequence_length"]`；Q/K/V/O 权重和输入形状相同。 | `Float[Tensor, " ... sequence_length d_model"]`；这个接口**使用 RoPE**，RoPE 宽度必须是每个 head 的 `d_model // num_heads`。 |
| `run_transformer_block` / `transformer_block` | `d_model`、`num_heads`、`d_ff`、`max_seq_len`、`theta` 是块结构参数；`d_model` 须能被 `num_heads` 整除；`weights: dict[str, Tensor]` 是单块参考 `state_dict`；`in_features`：`Float[Tensor, " batch sequence_length d_model"]`。 | 同形状输出；接口要求使用 RoPE。权重键及形状见下表。 |
| `run_transformer_lm` / `transformer_lm` | `vocab_size`、`context_length`、`d_model`、`num_layers`、`num_heads`、`d_ff`、`rope_theta` 定义模型；`weights: dict[str, Tensor]` 是完整模型参考 `state_dict`；`in_indices`：`Int[Tensor, " batch_size sequence_length"]`，且 `sequence_length ≤ context_length`。 | `Float[Tensor, " batch_size sequence_length vocab_size"]`；每个位置是下一词元的**未归一化**预测分数，接口要求使用 RoPE。 |

`run_transformer_block` 的 `weights` 键是：

| 键 | 形状与含义 |
| --- | --- |
| `attn.q_proj.weight`、`attn.k_proj.weight`、`attn.v_proj.weight` | 各为 `(d_model, d_model)`；行按各 head 的投影排列。 |
| `attn.output_proj.weight` | `(d_model, d_model)`，多头注意力输出投影。 |
| `ln1.weight`、`ln2.weight` | 各为 `(d_model,)`，块中的两处 RMSNorm 仿射权重。 |
| `ffn.w1.weight`、`ffn.w3.weight` | 各为 `(d_ff, d_model)`，前馈层权重。 |
| `ffn.w2.weight` | `(d_model, d_ff)`，前馈层权重。 |

`run_transformer_lm` 的 `weights` 还包含 `token_embeddings.weight`：`(vocab_size, d_model)`、`ln_final.weight`：`(d_model,)`、`lm_head.weight`：`(vocab_size, d_model)`；每层用 `layers.{i}.` 前缀接上表中的块权重键，`i` 从 `0` 到 `num_layers - 1`。原 Docstring 用 `{num_layers}` 表示层索引占位符，并非字面上的层数值；完整键名以实际 `state_dict` 为准。Q/K/V 权重在原文另写为 `(num_heads * (d_model / num_heads), d_model)`，输出投影写为 `((d_model / num_heads) * num_heads, d_model)`；这些数学表达保留原意，行仍按各 head 排列。

## 训练、优化与序列化

| 接口 / PDF Problem | 参数（中文释义） | 返回值及重要约束 |
| --- | --- | --- |
| `run_get_batch` / `data_loading` | `dataset`：一维整数 Token ID NumPy 数组；`batch_size`：批量大小；`context_length`：每条样本长度；`device`：如 `'cpu'`、`'cuda:0'` 的 PyTorch 设备字符串。 | 两个形状均为 `(batch_size, context_length)` 的 `torch.LongTensor`，分别是输入序列与对应的下一词元标签，均放在指定设备。 |
| `run_softmax` / `softmax` | `in_features: Float[Tensor, " ..."]`：任意形状输入；`dim`：归一化的维度。 | `Float[Tensor, " ..."]`，沿 `dim` 应用 Softmax 后形状不变。 |
| `run_cross_entropy` / `cross_entropy` | `inputs: Float[Tensor, " batch_size vocab_size"]`；第 `i` 行第 `j` 列是样本 `i` 对类别 `j` 的未归一化 logit。`targets: Int[Tensor, " batch_size"]` 是正确类别索引，取值范围 `[0, num_classes - 1]`。 | `Float[Tensor, ""]`，对 batch 中样本取平均的标量交叉熵。 |
| `run_gradient_clipping` / `gradient_clipping` | `parameters: Iterable[torch.nn.Parameter]`：待处理的参数集合；`max_l2_norm: float`：正数，所有梯度合并后的最大 ℓ2 范数。 | 返回 `None`；原位修改 `parameter.grad`。 |
| `get_adamw_cls` / `adamw` | 无形参。 | 测试通过 `get_adamw_cls()(...优化器参数...)` 实例化，所以这里返回的是可实例化的 AdamW 优化器类或等价构造器；原 Docstring 泛称返回 `torch.optim.Optimizer`。 |
| `run_get_lr_cosine_schedule` / `learning_rate_schedule` | `it`：查询的迭代号；`max_learning_rate`：`alpha_max`；`min_learning_rate`：`alpha_min`；`warmup_iters`：线性 warmup 的 `T_w`；`cosine_cycle_iters`：余弦阶段结束位置 `T_c`。 | 返回指定迭代的学习率标量。PDF 文中一次写为 `adapters.get_lr_cosine_schedule`，当前代码实际函数名是 `run_get_lr_cosine_schedule`。 |
| `run_save_checkpoint` / `checkpointing` | `model: torch.nn.Module`、`optimizer: torch.optim.Optimizer`、`iteration: int`（已完成迭代次数）、`out: str \| os.PathLike \| BinaryIO \| IO[bytes]`（输出路径或二进制文件对象）。 | 序列化模型、优化器和迭代号；未标注返回值。 |
| `run_load_checkpoint` / `checkpointing` | `src: str \| os.PathLike \| BinaryIO \| IO[bytes]`（已存 Checkpoint 的路径或文件对象）、`model` 和 `optimizer`（待恢复状态的对象）。 | 返回 `int`：保存时的迭代号；同时恢复传入对象的状态。 |

## BPE Tokenizer

| 接口 / PDF Problem | 参数（中文释义） | 返回值及重要约束 |
| --- | --- | --- |
| `get_tokenizer` / `tokenizer` | `vocab: dict[int, bytes]`：Token ID 到字节序列的映射；`merges: list[tuple[bytes, bytes]]`：按创建顺序排列的 BPE 合并对；`special_tokens: list[str] \| None`：可选特殊词元列表。 | 返回使用这些资料的 BPE Tokenizer；特殊词元编码时保持为单个 Token。具体对象需支持测试调用的 `encode`、`encode_iterable`、`decode`。 |
| `run_train_bpe` / `train_bpe` | `input_path: str \| os.PathLike`：训练语料路径；`vocab_size: int`：最终词表总大小，**包含特殊词元**；`special_tokens: list[str]`：加入词表的特殊词元；`**kwargs`：接口保留的额外关键字参数。 | `tuple[dict[int, bytes], list[tuple[bytes, bytes]]]`：`vocab` 是 Token ID→字节序列，`merges` 是按创建顺序排列的字节对。 |

**原文差异提醒：**`run_train_bpe` 的现有 Docstring 写道，特殊词元若出现在 `input_path` 中，会像普通字符串一样处理；Spring 2026 PDF 的 `train_bpe` Problem 则明确要求将特殊词元视为阻止跨越其跨度合并的硬边界，且不计入 merge 统计。这是原文件之间的差异，本指南没有擅自改写任何一个原文件。阅读与独立实现时应依据 PDF 的正式题目，并可向课程 staff 核对。

另见[测试文件阅读指南](测试文件阅读指南.md)了解当前测试实际覆盖范围。某些 PDF Problem（例如训练循环、生成和实验）没有适配器函数，也没有专门自动测试；其交付要求请直接查阅 PDF 与[任务索引](Assignment1任务索引.md)。
